# TVAPLAY

**TVAPLAY** — IPTV-платформа с серверной частью на **Go**, телевизионным интерфейсом на **JavaScript ES5 + jQuery 2.2.4** и отдельной административной панелью на **React**.

Проект ориентирован на просмотр IPTV с пульта телевизора, работу на устройствах с ограниченными возможностями браузера и единый сервер для авторизации, телеканалов, EPG и архива.

**Репозиторий:** https://github.com/unidiag/tvaplay

> **Совместимость — часть архитектуры.** TV UI не использует React: для LG webOS (включая старые версии), Samsung Smart TV, Android TV и других браузеров телевизоров поддерживается код в стиле ES5. Фактическая поддержка видеокодеков и нативного HLS зависит от устройства.

>

> **Актуальность:** документ описывает функциональность проекта с учётом последних доработок TVAPLAY. Часть этих изменений обсуждалась и применялась в рабочей версии после публичного коммита. Перед выпуском новой версии убедитесь, что соответствующие изменения кода опубликованы вместе с README.

## Возможности

### Телевизионное приложение

- **Прямой эфир (Live):** список телеканалов из серверного M3U-плейлиста, логотипы, выбор канала и полноэкранное воспроизведение.

- **EPG:** текущая телепередача, описание, постер, возрастной рейтинг и индикатор прогресса (если информация доступна).

- **Архив телепередач (Catch-up):** просмотр программы за доступный период, запуск архивной записи, пауза, перемотка и автоматический переход к следующей записи при наличии данных.

- **Поиск по архиву:** поиск передач по названию и переход к найденной записи.

- **Избранное:** выбор любимых телеканалов и режим показа только избранных в разделе «Каналы».

- **Категории:** группировка каналов по категориям из M3U (`group-title`), отображение названий категорий на выбранном языке.

- **Личный кабинет:** сведения об учётной записи и подписке (по мере подключения соответствующего API).

- **Устройства:** просмотр активных устройств, распознавание платформы/браузера и отзыв сессий.

- **Тест скорости:** измерение скорости соединения для оценки пригодности просмотра IPTV.

- **Язык интерфейса:** локализация телевизионного UI, включая сообщения загрузки, ошибки и категории.

- **Управление пультом:** навигация стрелками, ENTER и предусмотренными для телевизора клавишами.

Для загрузки каналов, списка передач и запуска видео используются отдельные индикаторы загрузки. Состояния загрузки и ошибки отображаются через локализованные строки интерфейса.

### Воспроизведение

TVAPLAY использует **нативный HLS** на поддерживаемых Smart TV. Для совместимых настольных браузеров предусмотрено воспроизведение через `hls.js` при доступности необходимых браузерных API.

В полноэкранном режиме:

| Действие | Live | Архив |

| --- | --- | --- |

| ENTER на канале/записи | Открыть полноэкранное видео | Открыть полноэкранное видео |

| ← / → | Выход из fullscreen согласно обработчику | Перемотка на 10 секунд |

| ENTER во время fullscreen | Выход из fullscreen | Пауза / продолжение |

| Другие клавиши | Выход из fullscreen | Выход из fullscreen, если не назначено другое действие |

Плеер сохраняет корректную геометрию изображения в полноэкранном режиме за счёт CSS-правил для элемента `\<video>`, включая `object-fit: fill`. **Ручное переключение 16:9 / 4:3 по клавише «Вниз» не входит в текущий интерфейс**: от него отказались в пользу стабильного отображения видео. Учтите, что `fill` может растягивать настоящее изображение 4:3.

| `be` | Беларуская | `uk` | Українська |

| `de` | Deutsch | `pl` | Polski |

| `fr` | Français | `es` | Español |

Категории плейлиста передаются как стабильные идентификаторы, например `sports`, `movies`, `documentary`, а подписи берутся из переводов:

## Авторизация и устройства

- Вход с подтверждением **SMS-кодом**.

- Короткоживущий **access JWT** для защищённых запросов и **refresh JWT** для продления сессии.

- Независимые refresh-сессии устройств с UID и JTI; ограничение числа устройств согласно настройке аккаунта.

- Проверка существующей сессии при запуске приложения, её обновление или повторный вход при необходимости.

- Просмотр устройств и удалённое завершение выбранной сессии.

- Проверки допустимого IP/GeoIP на защищённых TV-маршрутах.

В опубликованном `main.go` установлены `accessTTL = 10 минут` и `refreshTTL = 14 дней`. Эти значения следует сверять с актуальным кодом при развёртывании.

Ответы API возвращают машинные статусы (`OK`, `UNAUTHORIZED`, `INVALID_CODE`, `MAX_DEVICES` и т. п.). **Пользовательские сообщения сервера переводятся на английский**, а локализованный текст для пользователя формирует TV UI. Для последних изменений в этой области обновлены обработчики входа, EPG и управления устройствами.

### Особенности ES5 и старых Smart TV

- Использовать `var` и обычные функции вместо `let`, `const`, стрелочных функций и ES-модулей.

- Для запросов использовать `$.ajax()` / `XMLHttpRequest`.

- Не полагаться без проверки на `Promise`, `fetch`, `Map`, `Set` и современные CSS-возможности.

- Не делать CSS-переменные (`var(--x)`), CSS Grid и `100dvh` обязательными для базового интерфейса.

- Поддерживать навигацию пультом, видимый фокус и корректное освобождение обработчиков событий.

- Не использовать `.html()` для непроверенных данных сервера; предпочитать `.text()`.

## API v2 — интеграция с внешним биллингом

API v2 реализован в `api_v2.go` и предназначен для обмена данными об абонентах с внешним биллингом. Он не использует пользовательский access JWT: доступ определяется серверной настройкой `getSetting("api_key")`.

**Базовый путь:** `/api/v2/<API_KEY>/<FUNC>/...`

- `<API_KEY>` — секретный ключ из настройки `api_key`. Если настройка пуста, внешний API недоступен (`503`).
- `<FUNC>` — имя функции, чувствительное к регистру.
- `<LOGIN>` — значение `users.login`. Поиск выполняется по логину, а не по ID. Поддержка номеров как с `+`, так и без него зависит от установленной реализации `apiV2FindUser()`; убедитесь, что она нормализует телефонный логин, если это необходимо.
- Ответы имеют `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`. В случае успешного `getUsers` возвращается непосредственно массив; для `getUser` и операций изменения — JSON-объект.

### Справочник функций

| Метод | Маршрут после `/api/v2/<API_KEY>/` | Назначение |
| --- | --- | --- |
| `GET` | `getUsers` | Все пользователи |
| `GET` | `getUsers/<STATUS>` | Пользователи со статусом от `0` до `9` |
| `GET` | `getUser/<LOGIN>` | Данные пользователя, его сессии и подключённые пакеты |
| `GET` / `POST`* | `delUser/<LOGIN>` | Удалить refresh-сессии пользователя, сохранив его учётную запись |
| `GET` / `POST`* | `setUser/<LOGIN>/status/<VALUE>` | Установить статус пользователя |
| `GET` / `POST`* | `setUser/<LOGIN>/balance/<VALUE>` | Установить абсолютный баланс пользователя |
| `GET` / `POST`* | `setUser/<LOGIN>/info/<TEXT>` | Изменить дополнительную информацию пользователя |

* В обсуждаемой реализации `api_v2.go` изменяющие функции допускают оба метода. **Для внешней интеграции рекомендуется `POST`**: `GET` для мутаций может быть повторён браузером, кэшем или сетевым посредником. Существующие маршруты с параметрами в URL при этом сохраняются.

### `getUsers` — список абонентов

```http
GET /api/v2/<API_KEY>/getUsers
GET /api/v2/<API_KEY>/getUsers/1
```

Без `<STATUS>` возвращает всех абонентов, отсортированных по `id ASC`. При указании статуса допустимы значения **0–9** включительно. Некорректный статус возвращает `400 Bad Request`. Если совпадений нет — `[]`, а не `null`.

Пример сокращённого ответа:

```json
[
  {"id": 1, "login": "+375291111111", "status": 1, "balance": "12.50"},
  {"id": 2, "login": "+375292222222", "status": 1, "balance": "0.00"}
]
```

Реальные объекты содержат остальные разрешённые поля `models.User`; пароль, SMS-код и иные скрытые поля не должны выдаваться. Для фильтрованного варианта оба пользователя в примере имеют статус `1`.

### `getUser` — абонент, сессии, пакеты

```http
GET /api/v2/<API_KEY>/getUser/<LOGIN>
```

Возвращает объект с тремя полями:

- `user` — данные `models.User` без пароля и секретных полей; включая `last_paused_at`, если оно возвращается сервером.
- `sessions` — записи `UserRefreshToken` по `user_id`, отсортированные от новых к старым; поля `id`, `uid`, `ip`, `user_agent`, `created_at`, `expires_at` и `active`. `active` определяется сравнением `expires_at` с текущим временем. В массив могут входить **истёкшие сессии**, если их записи ещё хранятся в БД. `JTI` и refresh-токены не выдаются.
- `packages` — подключённые пакеты из `user_packages`, с информацией о каждом пакете (`models.Package`) и временем `enabled_at`. `disable_available_at` — момент, начиная с которого пакет можно отключить (через 24 часа после включения); значение `null` означает, что время подключения не известно.

Сокращённый пример:

```json
{
  "user": {
    "id": 15,
    "login": "+375291111111",
    "status": 1,
    "balance": "10.00",
    "info": "Договор №123",
    "last_paused_at": null
  },
  "sessions": [
    {
      "id": 23,
      "uid": "example-device-uid",
      "ip": "192.0.2.10",
      "user_agent": "Example TV Browser",
      "created_at": "2026-11-08T10:00:00Z",
      "expires_at": "2026-11-22T10:00:00Z",
      "active": true
    }
  ],
  "packages": [
    {
      "id": 2,
      "name": "Спорт",
      "code": "sport",
      "monthly_price": "8.00",
      "optional": true,
      "enabled_at": "2026-11-08T10:30:00Z",
      "disable_available_at": "2026-11-09T10:30:00Z"
    }
  ]
}
```

В примере приведены лишь ключевые поля; действительный ответ включает также остальные сериализуемые поля моделей.

### `delUser` — отзыв сессий

```http
POST /api/v2/<API_KEY>/delUser/<LOGIN>
```

Удаляет все строки из `user_refresh_tokens` для найденного пользователя. **Не удаляет пользователя из `users`, его пакеты или баланс.** Операция идемпотентна: если записей уже нет, вернётся `deleted_sessions: 0`.

```json
{
  "status": "OK",
  "login": "+375291111111",
  "deleted_sessions": 3
}
```

**Ограничение:** удаление refresh-сессий само по себе не гарантирует немедленный отзыв уже выпущенного access JWT. Такой JWT может продолжать действовать до истечения срока, если авторизационная middleware не проверяет отзыв сессии отдельно.

### `setUser` — изменение полей

#### Статус

```http
POST /api/v2/<API_KEY>/setUser/<LOGIN>/status/1
```

В рассмотренной реализации `apiV2SetUser()` принимает целые значения **0–7**. Это ограничение метода установки статуса не следует путать с фильтром `getUsers/<STATUS>`, который допускает **0–9**. Установка статуса административная: она не использует лимит пользовательской постановки на паузу и не обновляет `last_paused_at`.

#### Баланс

```http
POST /api/v2/<API_KEY>/setUser/<LOGIN>/balance/10.00
```

Устанавливает `users.balance = 10.00` (не пополнение и не списание). Значение передаётся как десятичная строка, без вычислений через `float64`. Разрешены отрицательные значения; не более двух знаков после запятой; применяется ограничение формата, установленное в `apiV2BalancePattern`. Пример: `-5.25` допустим.

#### Дополнительная информация

```http
POST /api/v2/<API_KEY>/setUser/<LOGIN>/info/%D0%94%D0%BE%D0%B3%D0%BE%D0%B2%D0%BE%D1%80%20%E2%84%96123
```

Изменяет `users.info`. `<TEXT>` — UTF-8, передаваемый с URL-кодированием, например `url.PathEscape()` в Go или `encodeURIComponent()` в JavaScript. В обсуждаемой реализации `+` в этом сегменте дополнительно заменяется пробелом (для совместимости с `urlencode`), поэтому **литеральный знак `+` в тексте не сохраняется**. Максимальная длина значения — **10 000 байт**.

Использование произвольного текста в пути URL имеет ограничения: `/` и `%2F` могут неодинаково обрабатываться прокси. Если понадобится передавать произвольные строки без таких ограничений, стоит добавить отдельный маршрут с JSON-телом запроса.

**Формат успешного ответа `setUser`:**

```json
{
  "status": "OK",
  "login": "+375291111111",
  "field": "balance",
  "value": "10.00"
}
```

Для `field: "status"` поле `value` — число, для `info` — строка. Ответ содержит фактическое значение, повторно загруженное из БД.

### Ошибки и HTTP-статусы

| HTTP | Условие |
| --- | --- |
| `200` | Запрос успешно обработан |
| `400` | Некорректный статус, баланс или поле `setUser` |
| `401` | Неверный API-ключ |
| `404` | Пользователь или функция не найдены, неверная структура URL |
| `405` | Недопустимый HTTP-метод |
| `500` | Ошибка БД или формирования ответа |
| `503` | Настройка `api_key` пуста; API отключён |

Пример:

```json
{"status": "ERROR", "message": "User not found"}
```

### Примеры запросов из Go

```go
package main

import (
    "fmt"
    "net/http"
    "net/url"
)

func main() {
    apiKey := "<API_KEY>" // Подставьте ключ из защищённой конфигурации
    login := "+375291111111"
    info := "Договор №123"

    endpoint := "https://tv.trianda.by/api/v2/" +
        url.PathEscape(apiKey) + "/setUser/" +
        url.PathEscape(login) + "/info/" +
        url.PathEscape(info)

    req, err := http.NewRequest(http.MethodPost, endpoint, nil)
    if err != nil {
        panic(err)
    }

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        panic(err)
    }
    defer resp.Body.Close()

    fmt.Println(resp.Status)
}
```

### Эксплуатация и безопасность

1. Используйте **HTTPS** и длинный случайный `api_key`. Реальный ключ нельзя публиковать в README и примерах.
2. Поскольку ключ содержится в пути, исключите URL `/api/v2/` из access-логов Nginx, аналитики, журналов прокси и мониторинга, либо настройте маскирование.
3. Ограничьте доступ к `/api/v2/` по IP-адресам сервера биллинга, если это возможно.
4. Не открывайте рабочие URL с ключом в адресной строке браузера без необходимости: они могут попасть в историю и журналы. Для изменяющих операций предпочтителен `POST`.
5. Проверьте, что выдача `apiV2PublicUser()` не включает `password`, `last_code`, refresh-токены и другие секреты; при расширении `models.User` обновляйте ограничения сериализации.
6. После изменения структуры БД, например добавления `user_packages.enabled_at`, выполните миграцию до запуска новых версий API.

## Запуск и сборка

### Требования

- **Go:** версия из `go.mod` (в опубликованной ветке указана `1.26.0`).

- **Node.js и npm:** для сборки React-панели и frontend-ресурсов.

- **MySQL:** основная база данных (GORM).

- Настроенные IPTV/HLS-источники, SMS-шлюз и, при необходимости, база GeoIP.

Перед запуском требуется подготовить **локальную конфигурацию**: параметры MySQL (`DSN`, `PREFIX`), SMS-шлюза (`SMSGATE`), серверов HLS и остальные значения, на которые ссылается Go-код. Не публикуйте пароли, ключи JWT, учётные данные SMS-шлюза и реальные данные пользователей.

### Разработка

```bash

git clone https://github.com/unidiag/tvaplay.git

cd tvaplay

go mod download

cd frontend

npm install

npm run build

cd ..

go run .

```

В опубликованном коде Go-сервер слушает `:8008`; корневая страница — `/`, React Admin — `/admin`. Запуск `go run .` включает debug-режим согласно текущему `main.go`.

### Production

Сборку фронтенда нужно выполнить **до** сборки Go, поскольку статические файлы включаются в бинарник. Базовая команда Go:

```bash

go build -o tvaplay .

./tvaplay

```

В проекте также есть сценарий `make`, но **не запускайте его без просмотра содержимого**: текущий вариант выполняет не только сборку, но и операции с Git-историей (`push --force`) и перезапуск `tvaplay.service`. Для локальной проверки безопаснее пользоваться командами выше.
